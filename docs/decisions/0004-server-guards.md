# 0004 防護：模型會出錯，程式來接

- 狀態：已採用

## 背景
模型偶爾漏標漢字讀音，或把該用中文寫的小提醒整段寫成日文。學習者會看到錯的讀音，或看不懂小提醒。提示詞只能降低出錯機率，不能保證。所以要做到：使用者不必多等、修好的內容存回紀錄、規則能用測試證明。

## 考慮過的選項
**A. 提示詞一直加規則**
- 優點：不必寫程式。
- 缺點：規則越多越容易被忽略，還是會錯。

**B. 錯了就整句重問**
- 優點：整句由模型重寫。
- 缺點：慢、貴，使用者要等兩次。

**C. 程式檢查加自動修（採用）**
- 優點：先顯示、不用等；修補規則可以寫測試。
- 缺點：程式規則要維護，可能誤判。

## 決定
分三層：
1. 提示詞要求固定格式，日文段標上語言，小提醒裡的日文用日文標記包起來。
2. 送出前由伺服器補上漏掉的讀音，並把小提醒裡沒包好的日文補上標記。
3. 小提醒不合格時，在背景請 Haiku 5.5 改寫，改好後替換聊天紀錄與小提醒本。

## 做法
- 送出前，伺服器把缺少的讀音補上；已經有的不動，日文標記以外的文字也不碰。
- 小提醒裡日文標記以外的中文少於 6 字，就判定不合格，在背景請模型改寫。
- 改寫結果依固定格式回傳；逾時 10 秒就保留原本的小提醒。
- 修補規則寫成測試，每次改動都會重跑。

## 取捨
- 用來查讀音的日文分詞工具偶爾不符合語境（一字多音）。實測讀音補標：詞級嚴格 95.2%（30 句、84 詞）。
- 「6 字」是經驗值，少數情況會誤判。實測小提醒改寫判斷：精確率 100%、召回率 90%（40 則）。
- 背景改寫多一次 Haiku 呼叫；超時就保留原本的小提醒。

## 何時重新評估
- 模型很少再出錯 → 拿掉背景改寫，省一次呼叫。
- 誤判變多 → 調整門檻並補測試。
- 換成本機模型 → 錯誤率不同，要重新量測。
