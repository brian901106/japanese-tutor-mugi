# 0005 降級：壞了也不亂答

- 狀態：已採用

## 背景
網路斷線、API 金鑰沒設、免費額度用完，外部服務一定會出問題。不能因為一個服務掛掉就整個 app 不能用，也不能讓模型亂答充數，更不想突然收到帳單。

## 考慮過的選項
**A. 出錯就彈出錯誤訊息**
- 優點：最簡單。
- 缺點：使用者會卡住，不知道接下來怎麼辦。

**B. 每個地方各寫自己的錯誤處理**
- 優點：可以各自客製。
- 缺點：規則散落、難維護，容易不一致。

**C. 統一的降級鏈，每個服務各有備案（採用）**
- 優點：規則集中一處；每個大腦標明自己能不能教日文。
- 缺點：目前聊天只有一條鏈，備案空間有限。

## 決定
- 聊天：依序嘗試可用的大腦，目前只有 Claude。全部失敗就把最後一個錯誤交給畫面，顯示「暫時不能回話」，不改用本機亂答。日語家教不做關鍵字備案，因為關鍵字備案不會教日文。
- 語音：免費額度用到 90% 時換下一層；VOICEVOX 沒有額度，不降級。

## 做法
```mermaid
flowchart LR
    A["語音請求"] --> B["雲端高階語音"]
    B -->|免費額度用到 90%| C["同語言的較低等級"]
    C --> D["Azure 語音"]
    D --> E["瀏覽器語音"]
```
- 聊天只有 Claude 一條路；失敗時畫面顯示暫時不能回話。
- 降到瀏覽器語音時，伺服器會告知手機改由瀏覽器自己發聲。

## 取捨
- 只有一條聊天大腦：Claude 斷線時家教就停擺，但不會亂答。
- 降到較低等級或瀏覽器語音時，音質差很多。
- 用量是本機統計，不是雲端帳單的即時數字。

## 何時重新評估
- 免費額度或價目改了 → 更新免費額度與換層門檻。
- 接上第二個大腦（例如本機模型）→ 加進聊天的備援清單，注意家教模式要求大腦能教日文。
- 雲端計費方式改了 → 更新花費估算與計費字數的算法。
