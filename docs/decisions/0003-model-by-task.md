# 0003 模型：看工作選大小

- 狀態：已採用

## 背景
專案有四種 AI 工作：聊天、改寫小提醒、速查、判斷練習。需要的聰明程度與等待時間各不相同。聊天要夠好；背景小工作要快又便宜，而且不能卡住聊天。換模型也不該改很多地方。

## 考慮過的選項
**A. 全部用同一個大模型**
- 優點：品質最好，只有一個設定。
- 缺點：背景小事也付高價，等待久。

**B. 模型名稱寫死在每個呼叫**
- 優點：直接。
- 缺點：想換要改很多地方，容易漏掉。

**C. 聊天與背景工作分開設定，預設都用 Haiku（採用）**
- 優點：換模型只改一處；背景預設快又便宜。
- 缺點：Haiku 偶爾寫不好，要靠防護與逾時（見 [0004](0004-server-guards.md)）。

## 決定
- 聊天預設跟著伺服器的模型設定（環境變數 ANTHROPIC_MODEL）；沒設就是 Haiku 5.5。設定頁可改選 Haiku 5.5、Sonnet 5.5 或 Opus 5.5。伺服器只接受清單內的模型，其他一律 400。
- 速查、小提醒改寫與判斷練習是背景工作，預設 Haiku 5.5；設定頁可分別改選（同樣只接受清單內的模型）。

## 做法
- 模型來源分兩層：伺服器的環境設定，加上設定頁的選項。請求帶來的模型名稱必須在白名單內。
- 手機選單與伺服器檢查用同一份清單，兩邊永遠一致。
- 背景工作（改寫、速查、判斷）各有自己的預設模型，與聊天分開。
- 每個可選模型都要有價格，花費估算才算得出來。

## 取捨
- Opus 5.5 的單價約為 Haiku 5.5 的 40 倍（10 萬 token 以內，依價目表）；品質更好，花費也更高。
- 花費用每日上限控制：環境變數 MUGI_DAILY_USD 預設 2 USD，達到上限回 429。估算：Haiku 5.5 約 5,800 句、Opus 5.5 約 150 句（皆為估算，依同一份實際用量按價目換算）。

## 何時重新評估
- 聊天品質不夠 → 設定改用 Opus 5.5，並留意每日上限。
- 背景改寫常常失敗 → 在設定頁把小提醒改寫的模型改大。
- 本機模型夠好 → 背景工作先搬到本機。
