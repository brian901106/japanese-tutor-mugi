# 開源前的安全審查：先當自己的攻擊者

## 背景
準備公開原始碼，擔心三件事：Claude 與語音服務的金鑰外洩、使用者個資外洩、執行開發伺服器的人被網站或同一網路的其他人攻擊。金鑰與個資不能出現在公開的程式、紀錄或 git 歷史裡。

## 決定
由獨立的紅隊代理做三輪靜態審查，每一條發現都在本機實測驗證，驗證不過的不算數。三輪各修一次。

## 做法
- 「本機」與「受信任」由連線的來源位址（socket）決定，不只看 Host 標頭：來源必須是回送位址（127.0.0.1、::1），Host 才會被採用，且只接受本機名稱與設定好的名稱。IP 位址只在區網模式（環境變數 MUGI_LAN）並附配對碼時才允許；區網來源（非回送位址）不論送什麼 Host，都不是本機、不受信任，不能改金鑰、預算，也不能登入或登出 ChatGPT。跨站請求與格式不對的寫入一律拒絕。
- 金鑰、設定檔、紀錄與快取檔不會被網頁讀取。
- 聊天每分鐘 20 次、同時最多 2 個請求；估計花費達每日上限就回 429。
- 人設圖片只存在瀏覽器裡，只收點陣圖格式，SVG 一律拒絕。
- 語音引擎只從指定位置啟動，找不到就拒絕，不搜尋工作資料夾。

## 取捨
- 跨站請求一律拒絕，會擋掉從其他網域的合法嵌入。
- 每日上限是估算值，不是帳單。
- 紅隊推測 DNS rebinding 可繞過 API 路徑；實測被 Vite 的 host 檢查擋下（403），仍保留自己的 host 檢查作縱深防禦。
- 開發伺服器不是正式部署，沒有登入與使用者帳號。

## 何時重新評估
- 要部署到公開網路 → 改用正式後端與登入。
- 改用其他 AI 供應商 → 重新檢查花費估算的價目表。
- 有人回報漏洞 → 再跑一輪紅隊審查。
